# Research: bind TF artifact file fingerprints to current path identity (#82)

## Grounded defect
At `445bf2087a8dff7e87d3feb6e57d6441b3bd052d`, the shared public `tf_build.fingerprint.fingerprint_tree` enumerates actual source tree entries and calls `_file_identity` for each regular artifact file. The latter uses a safe POSIX nonblocking descriptor, SHA256 hashes an opened inode and checks `fstat` size, device, inode and mtime before/after. It does **not** check `ctime_ns`, nor verify that the enumerated pathname still refers to the hashed inode. An atomic swap of a same-length TF feature file after opening leaves the FD and its fstats unchanged. It returns an apparently reproducible `TreeFingerprint` whose path now contains different bytes. A same-size rewrite of the opened file followed by restoring its mtime can pass the existing FD checks while silently reporting a mixed/stale digest. This is an artifact validation/reproducibility failure, not corpus semantics.

The wheel manifest script `scripts/wheel_manifest.py::_identity` already employs a post-read `lstat` dev/inode/size guard and `ctime_ns` comparison after PR #79. The tested source helper thus supplies a real implementation precedent. `tests/test_fingerprint.py` covers deterministic stable hashes, path ordering, exclusion, symlink/FIFO safety, and tree digest format but not those mutations.

## Real consumer and test contract
The public `fingerprint_tree` is used on generated TF trees by publication smoke tests and the project documentation examples; an incorrect identity could validate a different artifact from the one eventually published. The critical invariant is: at inspection completion, each recorded logical relative path must still refer to the same regular file inode whose bytes were hashed, and the open inode's observable metadata (including ctime) must not have changed during hashing. Tests will use actual POSIX regular files in a real artifact directory and deterministically inject an atomic rename-replacement or same-size rewrite with restored mtime inside the SHA256 `update` call. No mocks replace the production `fingerprint_tree` path, and no concurrent timing threads are needed.

## Scope and portability
Add a final `Path.lstat` comparison and `ctime_ns` to pre/post fstat within `_file_identity`. Count read bytes as currently done. Preserve stable input SHA256, tree digest and schema, UTF-8 paths, cache omission, and `manifest_path`. Keep symlink/FIFO fail-closed. On POSIX the existing `O_NOFOLLOW|O_NONBLOCK` protections apply; Windows has weaker guarantees and needs no false security promise. A full tree fingerprint is still *not* an atomic multi-file snapshot: modifications immediately after the last check or to already-enumerated other paths remain possible. Do not add a second full hashing pass, global locks, corpus-specific assumptions, or release publication.
