# Research: stable file identity in wheel manifest SHA256 evidence (#78)

## Actual defect and consumer boundary
At main `c9abd42946af92fa40548dda5ef67785597a7d37`, `scripts/wheel_manifest.py::_identity` (called for direct wheel, sdist, and every prepared wheelhouse dependency) rejects an initial symlink, then reopens by pathname using `Path.open`, hashes the opened bytes, and computes `bytes` from a fresh pathname `Path.stat`. There is no guarantee that the inspected pathname refers to the object hashed. A time-of-check/time-of-use replacement (or symlink replacement) can return successful evidence for the wrong file. The published archive's SHA256 can be individually true while its accompanying pathname and size refer to another object; the purported symlink exclusion is raceable. Distribution CI's archive build/test phases are independently implemented and cannot close this metadata-manifest race.

This is especially material for `.github/workflows/ci.yml` and manual `.github/workflows/release.yml`, both invoking the manifest script to attest SHA256 values for actual wheel/sdist assets. The existing public `tf_build.fingerprint._file_identity` employs `O_NOFOLLOW`, POSIX `O_NONBLOCK`, `os.fstat` before/after and file-descriptor SHA256; it provides a tested precedent for the same general invariant without requiring corpus-specific code. It does not currently check that the pathname still points at that FD after hashing.

## Threat model and test evidence
A legitimate CI artifact must be stable during inspection; we cannot make arbitrary paths immutable under a malicious process, but we must fail closed for observed mutation/replacement. A regular file switched to a symlink after preflight should not be followed; a pathname changed to a different inode while hashing should not yield a seemingly valid manifest. Real temporary regular files and symlinks, with deterministic race points wrapped around existing `Path.is_file` and SHA256 `update`, make these failures testable without executing candidate archive code or busy-loop timing races. The entire manifest JSON schema, SHA256, source SHA, and wheel selection logic stay unchanged.

## Design constraint and non-goals
Use one read-only FD to measure, hash, and verify a regular file. On POSIX demand `O_NOFOLLOW|O_NONBLOCK` on the open to reject raced symlinks and prevent FIFO blocking, then compare size, dev, inode, mtime_ns and ctime_ns via `fstat` before/after; compare final pathname `lstat` to the opened regular inode. Existing portable platforms without POSIX flags cannot claim identical nofollow guarantees; the post-read inode/path check still rejects observed replacements. Do not add a new package-level hash framework, general dependency locking, signatures, or release publication. The file can still be changed in the instant after the last check; manifest evidence is not a signed attestation or an atomic snapshot of multiple artifacts.
