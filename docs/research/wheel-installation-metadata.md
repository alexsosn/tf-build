# Research: WHEEL install scheme and compatibility drift (#70)

At reviewed main commit `c4b02dad836454a3f5009cba2a246e1bf3f7848f`, `scripts/compare_wheel_payloads.py` compares decompressed `tf_build/` files and package `METADATA` fields and optional entry points. It never checks `.dist-info/WHEEL`, and existing test-generated ZIP wheels omit `WHEEL` altogether. The same parity script gates both `.github/workflows/ci.yml` and manually dispatched `.github/workflows/release.yml` before a candidate release can be published.

The canonical PyPA binary distribution specification (https://packaging.python.org/en/latest/specifications/binary-distribution-format/) requires `.dist-info/METADATA`, `.dist-info/WHEEL`, and `.dist-info/RECORD`. `WHEEL` controls where the archive root installs (`Root-Is-Purelib` true/false), installer compatibility (`Wheel-Version`) and advertised compatibility (`Tag`), with optional `Build`; `Generator` identifies a build tool and can vary harmlessly between implementations. Although this package targets pure Python, the parity guard must not equate different installation schemes or incompatible wheel tags. The current real pipeline runs pip on each generated wheel; the test must also guard malformed intermediate assets statically without extracting candidate archive entries.

One source build might produce identical Python sources and package dependencies in two wheels but different `WHEEL` declarations. Require bounded `WHEEL` reads and a deterministic normalized install contract. Required singleton `Wheel-Version` must parse as a supported major 1 decimal version; singleton `Root-Is-Purelib` must be `true` or `false`; require nonempty `Tag` values (repeated tags compare order-independently) and at most one nonempty optional `Build`. Differences in runtime WHEEL declarations must fail; differing `Generator` must pass.

This is a release-engineering infrastructure guarantee, not a Text-Fabric ontology or parser decision. It does not replace full pip wheel validation, verify `RECORD` integrity, normalize tags against filenames, or publish a release. The current `wheel_manifest.py` independently binds the direct artifact's package/version and SHA256.
