# Research: POSIX descriptor-anchored TF artifact fingerprint traversal (#84)

## Actual observed hazard
On main `716b20e62e17d159ee76ae172f7f0f22e35a996d`, `src/tf_build/fingerprint.py` first enumerates file paths recursively in `_files` using `os.scandir(path)` and `DirEntry.is_symlink / is_dir(follow_symlinks=False)`. A checked nested directory can be atomically moved and replaced by a symlink **before** its recursive `os.scandir(Path(item.path))` call; `scandir` follows the new symlink. Later `_file_identity` opens complete path strings with `O_NOFOLLOW` only at final component, so a *parent* symlink still escapes the artifact. PR #83's final `path.lstat` protects a file's terminal entry, not its parent chain. This can hash an unrelated or sensitive external file into the published identity, despite a documented symlink-exclusion policy.

## Actual consumer and common contract
The public `fingerprint_tree` is used to attest complete generated TF trees, including nested `tf/` output and source feature references, without Text-Fabric runtime cache `.tf/`. Existing real tests prove ordered UTF-8 inventory, exact `tf-build-tree-sha256-v1` framing, cache exclusions, manifest omissions, FIFO safety, nofollow, and explicit symlink errors. Changing to descriptor-backed file hashing may reorder enumeration, but sorting records by relative UTF-8 names *before constructing the aggregate digest* preserves the public contract.

## POSIX APIs and guarantees
On POSIX Python, `os.open(path, O_RDONLY|O_DIRECTORY|O_NOFOLLOW)` can lock an actual directory inode; `os.scandir(dirfd)` enumerates that inode; `os.open(child_name, ..., dir_fd=dirfd)` opens an entry inside exactly that opened parent without resolving a replaced ancestor path. Likewise `os.stat(child_name, dir_fd=dirfd, follow_symlinks=False)` checks the same namespace. Keep one fd per recursion depth, close via `with os.fdopen` or explicit `try/finally: os.close(fd)`. The first top-level open must also be nofollow. Inside the opened directory, reject nested symlinks or special files before reaching into their referents; for regular entries, hash before releasing the parent fd.

The prior helper `_file_identity(name, path)` can accept optional fd-relative basename/parent fd internally; do not expose it publicly. The final lstat must be relative to the pinned parent fd, and retain pre/post opened-fd ctime, mtime, size, dev, ino and read-byte checks from #83. For directories, optionally check post-enumeration `fstat` vs final fd-relative `stat` for detected swaps. A separate root pathname lookup should be checked at end for rename/removal, but not relied on for descriptor security.

## Portability and limits
On Windows, `os.scandir(fd)` and `dir_fd` support cannot be assumed. Keep a legacy path traversal fallback for non-POSIX without claiming a security guarantee equivalent to POSIX; continue rejecting normally observed symlinks and nonregular files. FD-relative paths do not make a multi-file atomic snapshot or prevent a write after check, nor do they guarantee hostile hard-link-free policy. This is **not** a general secure archive extractor, a corpus ontology change, or a release operation.

## RED test strategy
Build real `artifact/nested/otype.tf` and `outside/secret.tf` with distinct bytes. Monkeypatch `tf_build.fingerprint.os.scandir` only at the nested *path-string* entry point: rename the original nested directory to `parked`, replace the pathname by a symlink to `outside`, and pass through to the real scandir. Old code fingerprints `nested/secret.tf` from outside, falsely succeeding. The fixed POSIX walker opens nested directories relative to their verified parent with O_NOFOLLOW, so either refuses the swap (when timed at directory open) or enumerates only the previously opened safe inode. A second deterministic open-hook may be used when adapting the exact timing. Assert the public fingerprint never includes outside bytes and still accepts stable nested trees.
