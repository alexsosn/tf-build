# Research: archive inspection and hash refer to one source file (#80)

## Actual source and release consumer
Main `da2fce20dc78bf4ed12d7a97a5788d3a7f97fe7c`, successful CI run `38156124704`. The manual release and normal CI workflows invoke `scripts/wheel_manifest.py` for release-candidate `tf-build==0.1.0rc1` wheel and sdist evidence. `build_wheel_manifest` opens the wheel ZIP, checks bounded `.dist-info/METADATA` Name, Version and uniqueness, closes that archive, and later calls `_identity(wheel)` for SHA256. `_sdist_identity` validates every tar entry and bounded `PKG-INFO` then independently calls `_identity(path)`. PR #79 changed `_identity` to open and hash a stable regular FD with before/after inode and timestamp checks, but cannot detect a replace-and-restore or replace-after-inspection-before-hashing *across those separate opens*.

## Reproducible failure class
In a Linux/Unix directory one process may `os.replace` a named wheel or sdist with another correctly named archive after the initial ZIP or TAR has been opened, while the already-open reader still sees its original inode. By injecting the swap just after `_check_package_identity` verifies valid original metadata, code completes old inspection and independently hashes the replacement archive. Its recorded checksum is true for the *unverified* second archive. A release buyer might then download those bytes despite the inspection's Name/Version checks proving only the first bytes. Test real ZIP and tar.gz on POSIX, using invalid embedded `Name`/ `Version` in replacement, without extracting or running any archive code. An alternate signature/hashing policy or full multi-artifact atomicity is not needed here.

## Relevant Python interfaces and scope
The standard library `zipfile.ZipFile` accepts an existing seekable binary file object, and `tarfile.open(mode="r:gz", fileobj=...)` accepts an opened binary stream. A scoped callable inspector can operate on the exact opened file held by `_identity`; then `seek(0)` and hash the same FD. `_identity` retains initial/last `fstat`, size, dev/inode, mtime_ns and ctime_ns and final pathname `lstat` checks, plus POSIX `O_NOFOLLOW`/`O_NONBLOCK` protections; if the filename changes to an alternate inode, the whole operation fails even if both archives happen to be valid. Wheelhouse entries can still call the same helper without an inspection callback. No changes to `wheel-manifest.json` format, archive path rules, release controls, public tf-build API or corpus semantics.

## Residual limits
No live filesystem read is cryptographically atomic against a concurrent adversary; a post-final-stat modification could still occur, and separate dependencies remain a non-atomic inventory. The fix ensures the *archive inspection and hash within each named asset* share one validated opened descriptor and rejects observed pathname substitution. Normal builds continue to use only one sequential SHA256 pass.
